# FlagGems NVIDIA RTX 4090 性能测试报告

> 本报告按 `R9700_FLAGGEEM_RESULTS.md`（AMD Radeon R9700）的方案与章节结构编写，使用同一 FlagGems commit、同一 Triton 主版本、同一套官方 core shape 和同一套统计脚本，因此两份报告的 speedup 可以逐行对比。绝对耗时不可跨机对比，因为 PyTorch 基线本身是不同后端与版本。附录 A 给出两台机器的直接对比。

## 1. 结论摘要

- 测试 10 类算子、FP16/BF16、5 个官方 core shape，共 100 个 shape/dtype 用例。
- Kernel 模式：39 个加速超过 2%，38 个近似持平，23 个慢超过 2%。
- Operator 模式：14 个加速超过 2%，26 个近似持平，60 个慢超过 2%。
- 39 个 Kernel 加速用例中，14 个保留实际调用收益，25 个被派发/启动开销抵消。
- 14 个保留收益的用例构成：Softmax 8 个、BMM 2 个、LayerNorm 2 个、RMSNorm 2 个；Sum 与 Mean 一个都没保住。
- 实际调用最值得保留：大型 Softmax（最高 6.73×）、最大 LayerNorm（最高 4.56×）、最大 RMSNorm（约 1.31×）。
- MM/BMM 没有整体收益，但退化幅度温和（0.92–0.99×），对 cuBLAS 已接近持平；小型点算子不适合当前 FlagGems NVIDIA 路径。
- 容器自带的 Triton 3.7.0 与 FlagGems 5.4.0 不兼容，会导致 kernel 启动参数错位并触发段错误；本报告全部数据在降级后的 Triton 3.6.0 下产生，详见 4.1 节。

### 2.1 设备选择与频率锁定

本机装有 2 张 RTX 4090，测试期间两张卡都空闲，全部测量只使用逻辑 GPU 0（BDF `0000:a8:00.0`）串行执行。

| PyTorch/CUDA 逻辑编号 | BDF | 本次使用 |
|---|---|---|
| 0 | `a8:00.0` | 是 |
| 1 | `d8:00.0` | 否 |

RTX 4090 是消费级卡，默认会因 450 W 功耗墙持续降频。锁频前实测满载 100 秒，频率由 2415 MHz 一路掉到 2295 MHz（漂移约 5%），温度升到 70 °C；这个幅度足以污染三轮之间的对比。因此锁定在 2100 MHz——该点位低于功耗墙，实测满载 80 秒频率零漂移、功耗约 405 W。

benchmark 全程共采样 226 次，GPU 忙碌期间 SM 频率恒为 2100 MHz（唯一值），温度 51–67 °C。采样记录：`run_tests_results/env/gpu_monitor.csv`。这是本报告与 AMD 侧方法学的唯一一处差异（AMD 侧未锁频）。

## 3. 测试范围与方法

- 算子：`mm`、`bmm`、`softmax`、`sum`、`mean`、`mul`、`sub`、`div`、`layer_norm`、`rms_norm`。
- Dtype：FP16、BF16。FP32 MM 在本机正确性测试中通过，但为与 AMD 侧口径一致，性能测试仍只覆盖 FP16/BF16。
- Shape：仓库官方 `benchmark/core_shapes.yaml` 和 benchmark 内置 core shapes；没有创建自定义 shape。
- 基线：原生 PyTorch CUDA。
- `speedup = PyTorch latency / FlagGems latency`；大于 `1.0×` 表示 FlagGems 更快。
- 分类：`>1.02×` 为加速，`0.98–1.02×` 为近似持平，`<0.98×` 为退化。
- 每种模式先预热，再正式运行 3 次；逐"算子 + dtype + shape"取三轮中位数。
- 算子/dtype 汇总先取 5 个官方 shape 的 speedup 中位数；绝对耗时取对应中位 speedup 代表 shape 的三轮中位耗时，保证三项指标来自同一 shape。
- 逐 shape 表同时保留三轮原始结果和三轮中位数。
- `--warmup 1000 --iter 500` 在本 benchmark 中是 1000 ms 预热预算和 500 ms 测量预算，不是固定调用次数。
- Kernel 模式通过 `triton.testing.do_bench(..., return_mode="median")` 主要测量 GPU 稳态时间。
- Operator 模式使用同步前后的墙钟时间，包含 Python、ATen/FlagGems 派发、Kernel launch 和 GPU 执行；不包含 `flag_gems.use_gems()` 上下文进入/退出本身。

### 3.1 正确性门禁

- 通过：190 项。
- 失败：6 项，均为 `mm` 在 `M=1,N=1,K=32` 与 `M=15,N=160,K=1024` 上的 FP16/BF16 用例；Triton 配置申请 128 KiB 共享内存，超过硬件 100 KiB 上限。
- 跳过：1 项官方测试。
- 失败的 6 个 shape 不在 benchmark core shape 内；benchmark 实际使用的 5 个 mm shape 已单独冒烟验证全部 SUCCESS，性能数据不受影响。
- FP16/BF16 的其余 9 类目标算子全部通过。

## 4. 测试命令

### 4.1 修正 Triton 版本并固定环境

容器自带 Triton `3.7.0`，而 FlagGems `5.4.0.dev50` 的 `src/flag_gems/utils/libentry.py` 有三处硬编码版本闸门 `if major_version == 3 and 3 <= minor_version <= 6`。Triton 3.7 落入未适配的 `else` 分支，constexpr 参数（`BLOCK_M/N/K`、`num_stages` 等）在 kernel 启动时被静默丢弃，导致参数列表错位：`sub` 在 `(1,)` 单元素张量上抛 `TypeError: 'str' object cannot be interpreted as an integer`，随后 CUDA context 损坏、pytest 进程段错误，`mean`/`div`/`layer_norm`/`rms_norm` 四个算子无法执行。

FlagGems 自带的 `src/flag_gems/backends.yaml` 对 `nvidia-cuda128` 和 `nvidia-cuda133` 都钉 `triton==3.6.0`；上游 master（`7f2cc832d`）自 `424111a97` 以来对 `libentry.py` 零改动；AMD 对照机用的也是 Triton 3.6.0。

```bash
cd /target/FlagGems
set -o pipefail
unset TRITON_PRINT_AUTOTUNING
export CUDA_VISIBLE_DEVICES=0
export GEMS_VENDOR=nvidia

# 备份容器自带的 Triton 以便还原
cp -a /usr/local/lib/python3.12/dist-packages/triton \
      /usr/local/lib/python3.12/dist-packages/triton-3.7.0+gitb4e20bb.nv26.5.dist-info \
      /target/backup_triton_ngc/

pip install "triton==3.6.0"

# 清理 3.7 生成的 kernel 缓存
rm -rf /root/.flaggems/code_cache /root/.triton/cache
```

## 5. Kernel 模式测试与 FlagGems/PyTorch 比较

- 总计：加速 39/100，近似持平 38/100，退化 23/100。
- 86/100 个用例三轮 speedup 波动不超过 5%；超标的 14 个全部是耗时 3–13 µs 的微型 shape，属于计时分辨率下限问题（见 8.4）。
- LayerNorm 两种 dtype 的 5 个 shape 全部加速，是本机收益最大的算子。
- Softmax 两种 dtype 各有 4/5 个 shape 加速；RMSNorm 3–4/5 加速。
- MM 两种 dtype 各有 3–4/5 个 shape 慢于 PyTorch；BMM 逐 shape 分布分散（快 1–2 个、平 1 个、慢 2–3 个），但中位数接近持平（`0.976×`/`0.992×`）。
- Mul 全部 10 个用例的中位 speedup 落在 `0.999–1.001×` 之间，是最接近持平的算子。
- Sum、Mean 对 shape 高度敏感，只在中小 shape 上有收益。

## 6. Operator 模式测试与 FlagGems/PyTorch 比较

- 总计：加速 14/100，近似持平 26/100，退化 60/100。
- 88/100 个用例三轮 speedup 波动不超过 5%。
- 大型 Softmax `[64,512,512]` 达到 6.63–6.73×，是全部 200 个测量点中的最高值；`[4096,4096]` 约 3.09–3.13×。

## 8. 限制与解释

1. 本报告是算子微基准，不等同于完整模型端到端吞吐。
2. Operator 模式使用 CPU 墙钟，微秒级用例容易受调度与时钟噪声影响；因此逐 shape 表同时给出三轮原始结果。
3. Kernel 与 Operator 使用不同计时机制，绝对 latency 不应跨模式直接相减；应重点比较各自相对 PyTorch 的 speedup。
4. Kernel 模式的微型 shape 撞到了计时分辨率下限。`[64,64]`、`[256,256]`、`[2,384,384]` 这类 shape 单次耗时只有 3–13 µs，CUDA event 计时呈现约 1 µs 的量化格点（实测值集中在 4096 ns、5120 ns、9216 ns），一个量化步长就等于 20–25% 的 speedup 波动。14 个三轮波动超过 5% 的用例全部落在这一档。AMD 侧同类 shape 耗时更长且计时更细，所以只有 1 个用例超标——这是测量分辨率差异，不是稳定性差异。这些微型 shape 的 speedup 应视为"约等于 1.0"而非精确值。
5. `bmm` 在 `[16,4096,4096]` BF16 上的 `2.080×` 不是 FlagGems 的收益，而是 PyTorch 基线的异常。FlagGems 两种 dtype 耗时几乎相同（16.66 ms，同一个 Triton kernel），而 PyTorch 的 BF16 路径要 34.65 ms，比它自己的 FP16 路径（16.18 ms）慢 2.14 倍；同算子其他 shape 无此现象（`[2,4096,4096]` 上 BF16 仅比 FP16 慢 8%，`[16,2048,2048]` 上两者持平）。这是 cuBLAS 在该特定批量形状下的 BF16 路径回退，解读为"FlagGems 快一倍"会产生误导。
6. GPU 锁定在 2100 MHz，低于该卡默认 boost（未锁频时满载稳态约 2295 MHz），因此绝对耗时不代表该卡满速性能；但对 speedup 影响很小，因为 PyTorch 与 FlagGems 在同一频率下测量。
7. 本机 CPU 频率调节处于低档（`scaling MHz: 27%`），会放大 Operator 模式中 Python/派发部分的开销。跨机对比 Operator 模式的小 shape 结果时需注意这一点。
8. `mm` 的 6 个 FP16/BF16 正确性失败源于 FlagGems 的 NVIDIA tuning 档位申请 128 KiB 共享内存，超过 Ada 的 100 KiB 上限。这与 AMD 侧 FP32 MM 的失败同源——该配置面向共享内存更大的 Hopper（228 KiB），在 Ada 消费卡上放不下。
9. FlagGems 5.4.0 不支持 Triton 3.7。本报告全部数据在 Triton 3.6.0 下产生；在 Triton 3.7 环境下直接运行会出现 kernel 启动参数错位与段错误，所得数据不可信。
10. NVIDIA 后端未安装 C++ 扩展（`flag-gems-cpp-cuda`），使用的是通用 Triton kernel 及 NVIDIA tuning/heuristics，与 AMD 侧的纯 Triton 路径口径一致。安装 C++ 扩展后 Operator 模式的派发开销预计会明显下降。
11. 结论只适用于当前 FlagGems commit、CUDA/PyTorch/Triton 版本和官方 core shapes。

    parser.add_argument("--output-dir", type=Path, required=True)
    return parser.parse_args()


def flatten_run(path: Path) -> dict[tuple[str, str, str, int, str], dict[str, Any]]:
    payload = json.loads(path.read_text())
    flattened: dict[tuple[str, str, str, int, str], dict[str, Any]] = {}

    for value in payload.values():
        for detail in value["details"]:
            mode = detail["mode"]
            op_name = detail["op_name"]
            dtype = detail["dtype"].removeprefix("torch.")
            for case_index, result in enumerate(detail["result"]):
                shape_key = json.dumps(
                    result["shape_detail"], sort_keys=True, separators=(",", ":")
                )
                key = (mode, op_name, dtype, case_index, shape_key)
                if key in flattened:
                    raise ValueError(f"Duplicate benchmark case in {path}: {key}")
                flattened[key] = {
                    "mode": mode,
                    "operator": op_name,
                    "dtype": dtype,
                    "case_index": case_index,
                    "shape_detail": result["shape_detail"],
                    **{metric: result.get(metric) for metric in METRICS},
                }

    return flattened


def aggregate(inputs: list[Path]) -> tuple[list[dict[str, Any]], list[dict[str, Any]]]:
    runs = [flatten_run(path) for path in inputs]
    expected_keys = set(runs[0])
    for path, run in zip(inputs[1:], runs[1:], strict=True):
        if set(run) != expected_keys:
            missing = expected_keys - set(run)
            extra = set(run) - expected_keys
            raise ValueError(f"Case mismatch in {path}: missing={missing}, extra={extra}")

    cases: list[dict[str, Any]] = []
    for key in sorted(expected_keys):
        records = [run[key] for run in runs]
        speedups = [record["speedup"] for record in records]
        latency_base_runs = [record["latency_base"] for record in records]
        latency_runs = [record["latency"] for record in records]
        median_speedup = median(speedups)
        spread_pct = (
            (max(speedups) - min(speedups)) / median_speedup * 100
            if median_speedup
            else None
        )
        aggregated = {
            "mode": records[0]["mode"],
            "operator": records[0]["operator"],
            "dtype": records[0]["dtype"],
            "case_index": records[0]["case_index"],
            "shape_detail": records[0]["shape_detail"],
            "latency_base_runs": latency_base_runs,
            "latency_runs": latency_runs,
            "speedup_runs": speedups,
            "speedup_spread_pct": spread_pct,
            "unstable_over_5pct": spread_pct is not None and spread_pct > 5,
        }
        for metric in METRICS:
            values = [record[metric] for record in records if record[metric] is not None]
            aggregated[f"median_{metric}"] = median(values) if values else None
        cases.append(aggregated)

    grouped: dict[tuple[str, str], list[dict[str, Any]]] = defaultdict(list)
    for case in cases:
        grouped[(case["operator"], case["dtype"])].append(case)

    summaries: list[dict[str, Any]] = []
    for (operator, dtype), group in sorted(grouped.items()):
        speedups = [case["median_speedup"] for case in group]
        spreads = [case["speedup_spread_pct"] for case in group]
        median_speedup = median(speedups)
        representative = min(
            group, key=lambda case: abs(case["median_speedup"] - median_speedup)
        )
        summaries.append(
            {
                "mode": group[0]["mode"],
                "operator": operator,
                "dtype": dtype,
                "cases": len(group),
                "representative_case_index": representative["case_index"],
                "representative_shape_detail": representative["shape_detail"],
                "median_latency_base": representative["median_latency_base"],
                "median_latency": representative["median_latency"],
                "median_speedup": median_speedup,
                "min_speedup": min(speedups),
                "max_speedup": max(speedups),
                "faster_over_2pct": sum(value > 1.02 for value in speedups),
                "near_parity_within_2pct": sum(0.98 <= value <= 1.02 for value in speedups),
                "slower_over_2pct": sum(value < 0.98 for value in speedups),
                "unstable_cases_over_5pct": sum(
                    case["unstable_over_5pct"] for case in group
                ),
                "median_case_spread_pct": median(spreads),
                "max_case_spread_pct": max(spreads),
            }
        )

    return cases, summaries


def write_outputs(
    output_dir: Path,
    inputs: list[Path],
    cases: list[dict[str, Any]],
    summaries: list[dict[str, Any]],
) -> None:
    output_dir.mkdir(parents=True, exist_ok=True)
    modes = {case["mode"] for case in cases}
    if len(modes) != 1:
        raise ValueError(f"Expected one benchmark mode, got: {sorted(modes)}")

            },
            "source_runs": [str(path) for path in inputs],
        },
        "operator_summary": summaries,
        "cases": cases,
    }
    (output_dir / "median_results.json").write_text(

    with (output_dir / "median_results.csv").open("w", newline="") as handle:
        fieldnames = [

def case_key(case: dict[str, Any]) -> tuple[str, str, int, str]:
    return (
        case["operator"],
        case["dtype"],
        case["case_index"],
        json.dumps(case["shape_detail"], sort_keys=True, separators=(",", ":")),

def classify(speedup: float) -> str:
    if speedup > 1.02:
        return "faster"
    if speedup < 0.98:
        return "slower"
    return "near_parity"


def load_cases(path: Path, expected_mode: str) -> dict[tuple[str, str, int, str], dict[str, Any]]:
    payload = json.loads(path.read_text())
    mode = payload["metadata"].get("mode")
    if mode != expected_mode:
        raise ValueError(f"Expected {expected_mode} data in {path}, got {mode}")
    return {case_key(case): case for case in payload["cases"]}


def compare(
    kernel_path: Path, operator_path: Path
) -> tuple[list[dict[str, Any]], list[dict[str, Any]], dict[str, int]]:
    kernel_cases = load_cases(kernel_path, "kernel")
    operator_cases = load_cases(operator_path, "operator")
    if set(kernel_cases) != set(operator_cases):
        raise ValueError("Kernel and operator case sets do not match")

    comparisons: list[dict[str, Any]] = []
    for key in sorted(kernel_cases):
        kernel = kernel_cases[key]
        operator = operator_cases[key]
        kernel_speedup = kernel["median_speedup"]
        operator_speedup = operator["median_speedup"]
        kernel_class = classify(kernel_speedup)
        operator_class = classify(operator_speedup)
        comparisons.append(
            {
                "operator": kernel["operator"],
                "dtype": kernel["dtype"],
                "case_index": kernel["case_index"],
                "shape_detail": kernel["shape_detail"],
                "kernel_speedup": kernel_speedup,
                "operator_speedup": operator_speedup,
                "speedup_delta": operator_speedup - kernel_speedup,
                "operator_to_kernel_ratio": operator_speedup / kernel_speedup,
                "kernel_class": kernel_class,
                "operator_class": operator_class,
                "kernel_gain_retained": (
                    kernel_class == "faster" and operator_class == "faster"
                ),
                "kernel_gain_lost": (
                    kernel_class == "faster" and operator_class != "faster"
                ),
                "operator_unstable_over_5pct": operator["unstable_over_5pct"],
            }
        )

    grouped: dict[tuple[str, str], list[dict[str, Any]]] = defaultdict(list)
    for case in comparisons:
        grouped[(case["operator"], case["dtype"])].append(case)

    summaries: list[dict[str, Any]] = []
    for (operator, dtype), group in sorted(grouped.items()):
        kernel_speedups = [case["kernel_speedup"] for case in group]
        operator_speedups = [case["operator_speedup"] for case in group]
        kernel_median_speedup = median(kernel_speedups)
        operator_median_speedup = median(operator_speedups)
        summaries.append(
            {
                "operator": operator,
                "dtype": dtype,
                "cases": len(group),
                "kernel_median_speedup": kernel_median_speedup,
                "operator_median_speedup": operator_median_speedup,
                "operator_minus_kernel_median": (
                    operator_median_speedup - kernel_median_speedup
                ),
                "median_case_speedup_delta": median(
                    case["speedup_delta"] for case in group
                ),
                "kernel_faster_cases": sum(
                    case["kernel_class"] == "faster" for case in group
                ),
                "operator_faster_cases": sum(
                    case["operator_class"] == "faster" for case in group
                ),
                "kernel_gains_retained": sum(
                    case["kernel_gain_retained"] for case in group
                ),
                "kernel_gains_lost": sum(case["kernel_gain_lost"] for case in group),
                "operator_unstable_cases": sum(
                    case["operator_unstable_over_5pct"] for case in group
                ),
            }
        )

    totals = {
        "cases": len(comparisons),
        "kernel_faster_cases": sum(
            case["kernel_class"] == "faster" for case in comparisons
        ),
        "operator_faster_cases": sum(
            case["operator_class"] == "faster" for case in comparisons
        ),
        "kernel_gains_retained": sum(
            case["kernel_gain_retained"] for case in comparisons
        ),
        "kernel_gains_lost": sum(case["kernel_gain_lost"] for case in comparisons),
        "operator_unstable_cases": sum(
            case["operator_unstable_over_5pct"] for case in comparisons
        ),
    }
    return comparisons, summaries, totals

#!/usr/bin/env python3
"""Cross-platform table: NVIDIA medians vs the AMD reference report.

AMD numbers are parsed straight out of sections 5.1 and 6.1 of the reference
markdown so the comparison can never drift from the published report.
"""

from __future__ import annotations

import argparse
import json
import re
from pathlib import Path
from typing import Any


ROW = re.compile(
    r"^\|\s*(\w+)\s*\|\s*(float16|bfloat16)\s*\|\s*([\d.]+)\s*\|\s*([\d.]+)\s*\|\s*([\d.]+)×\s*\|$"
)


def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser()
    parser.add_argument("--amd-report", type=Path, required=True)
    parser.add_argument("--kernel", type=Path, required=True)
    parser.add_argument("--operator", type=Path, required=True)
    parser.add_argument("--output", type=Path, required=True)
    return parser.parse_args()


def parse_amd(path: Path) -> dict[str, dict[tuple[str, str], float]]:
    """Return {'kernel'|'operator': {(op, dtype): median_speedup}}."""
    section = None
    out: dict[str, dict[tuple[str, str], float]] = {"kernel": {}, "operator": {}}
    for line in path.read_text().splitlines():
        if line.startswith("### 5.1"):
            section = "kernel"
            continue
        if line.startswith("### 6.1"):
            section = "operator"
            continue
        if line.startswith("### ") or line.startswith("## "):
            if section and out[section]:
                section = None
            continue
        if section is None:
            continue
        m = ROW.match(line.strip())
        if m:
            out[section][(m.group(1), m.group(2))] = float(m.group(5))
    for mode, table in out.items():
        if len(table) != 20:
            raise ValueError(f"Parsed {len(table)} AMD {mode} rows, expected 20")
    return out


def load_medians(path: Path) -> dict[tuple[str, str], float]:
    payload = json.loads(path.read_text())
    return {
        (s["operator"], s["dtype"]): s["median_speedup"]
        for s in payload["operator_summary"]
    }


def table(
    amd: dict[tuple[str, str], float],
    nv: dict[tuple[str, str], float],
    label: str,
) -> list[str]:
    lines = [
        f"| 算子 | dtype | AMD R9700 {label} 中位 | RTX 4090 {label} 中位 | 差值 |",
        "|---|---|---|---|---|",
    ]
    for key in sorted(nv):
        a, n = amd[key], nv[key]
        lines.append(f"| {key[0]} | {key[1]} | {a:.3f}× | {n:.3f}× | {n - a:+.3f} |")
    return lines


def main() -> None:
    args = parse_args()
    amd = parse_amd(args.amd_report)
    nv_kernel = load_medians(args.kernel)
    nv_operator = load_medians(args.operator)

    missing = set(nv_kernel) ^ set(amd["kernel"])
    if missing:
        raise ValueError(f"Operator/dtype sets differ: {sorted(missing)}")

    out: list[str] = []
    out.append("### 8.1 Kernel 模式中位 speedup 对比")
    out.append("")
    out += table(amd["kernel"], nv_kernel, "Kernel")
    out.append("")
    out.append("### 8.2 Operator 模式中位 speedup 对比")
    out.append("")
    out += table(amd["operator"], nv_operator, "Operator")
    args.output.write_text("\n".join(out) + "\n")

    print("mode      op/dtype 组数 | NVIDIA 更优 | AMD 更优")
    for label, nv, key in (
        ("kernel", nv_kernel, "kernel"),
        ("operator", nv_operator, "operator"),
    ):
        better = sum(nv[k] > amd[key][k] for k in nv)
        print(f"{label:9} {len(nv):>10} | {better:>10} | {len(nv) - better:>7}")
    print(f"written {args.output}")


if __name__ == "__main__":
    main()

## 附录 A. 与 AMD R9700 的横向对比

> AMD 报告模板之外的补充章节。两台机器使用同一 FlagGems commit、同一 Triton 主版本、同一套官方 core shape 和同一套统计脚本，因此 speedup 可以直接对比；绝对耗时不可对比，因为 PyTorch 基线本身是不同的后端和版本。下表由 `compare_with_amd.py` 直接解析 AMD 报告的 5.1/6.1 表格生成，不存在手工转录。

- Kernel 模式 20 个算子/dtype 组中，RTX 4090 在 12 组上 speedup 更高，AMD 在 8 组上更高。
- Operator 模式 20 组中，RTX 4090 在 10 组上更高，AMD 在 9 组上更高，1 组完全持平；其中 Mul、Sub、Div 共 6 组的差值都在 `0.02` 以内，属于噪声，真正有意义的差异集中在下面两条。
- RTX 4090 优势最明显：LayerNorm Kernel（`+0.85 ~ +1.22`）、MM（Kernel `+0.25`，Operator `+0.21 ~ +0.23`）、Softmax Operator（`+0.74`）。
- AMD 优势最明显：RMSNorm Operator（`+0.82 ~ +0.83`）、Sum Operator（`+0.49 ~ +0.51`）、Mean Operator（`+0.08 ~ +0.14`）。
- 一条规律：AMD 侧 FlagGems 的 MM 明显打不过 rocBLAS（`0.70×`），而在 4090 上对 cuBLAS 已接近持平（`0.95×`）；BMM 同样由 `0.94×` 提升到 `0.98×`。
- 一条相反的规律：4090 上 PyTorch 小算子的派发极快（4–6 µs），而 FlagGems 的 Python 派发开销是 16–53 µs，所以小 shape 的算子级退化比 AMD 侧更严重。
